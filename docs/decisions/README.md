# Decisions

Why Hyper is built the way it is: one entry per choice that shapes the code.
The specs say what the system does; an entry keeps the reason, so a later change can tell a deliberate constraint from an accident.

An entry states the **Decision** (with where the code makes it), **Why**, and its **Cost**.
It links to the spec that holds the details rather than repeating them.
When a later decision changes an earlier one, update the earlier entry to say so and link the later one.
